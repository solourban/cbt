# CBT 서비스 수동 QA 테스트 순서표

## 목적

`service-qa-checklist.md`는 전체 범위 체크리스트이고, `qa-run-001.md`는 실제 오류 로그다.

이 문서는 실제 화면을 어떤 순서로 눌러볼지 정하는 실행 순서표다.

---

## 테스트 전 준비

1. 배포 화면 접속
   - `https://cbt-lac.vercel.app/`
2. 브라우저 개발자도구 Console 열기
3. 오류가 발생하면 화면 증상과 Console 오류를 함께 기록
4. 오류는 바로 수정하지 않고 `docs/qa-run-001.md`에 BUG 번호로 추가

---

## Phase 3. 채점 유형별 최소 테스트

목표: 모든 문제를 완벽히 검토하기 전에, 채점 유형별로 서비스가 멈추는지 확인한다.

### 3-1. 단답형

| 순서 | 테스트 | 입력값 | 기대 결과 | 기록 |
|---:|---|---|---|---|
| 1 | 공란 채점 | 빈칸 | 0점 또는 안내 |  |
| 2 | 오답 채점 | 아무답 | 오답 피드백 |  |
| 3 | 부분정답 | 핵심어 일부 | 부분점수 또는 누락 안내 |  |
| 4 | 정답 채점 | 핵심어 전체 | 정답 처리 |  |

### 3-2. 서술형

| 순서 | 테스트 | 입력값 | 기대 결과 | 기록 |
|---:|---|---|---|---|
| 1 | 짧은 답안 | 핵심어 1개 | 일부 점수 |  |
| 2 | 긴 답안 | 문장형 답안 | 채점 결과 표시 |  |
| 3 | 공란 | 빈칸 | 0점 또는 안내 |  |

### 3-3. 계산형

| 순서 | 테스트 | 입력값 | 기대 결과 | 기록 |
|---:|---|---|---|---|

| 2 | 숫자만 입력 | 정답 수치 | 정답 처리 |  |
| 3 | 단위 포함 | 수치+단위 | 허용 또는 피드백 |  |
| 4 | 반올림값 | 근사값 | 허용 여부 확인 |  |

### 3-4. 소문항형

| 순서 | 테스트 | 입력값 | 기대 결과 | 기록 |
|---:|---|---|---|---|

## Phase 6. 오류 기록 방식

오류가 나오면 다음 형식으로 `docs/qa-run-001.md`에 추가한다.

```txt

번호:

브라우저:
구분:
위치:
입력값:

재현 방법:

추정 원인:
처리 상태:
비고:
```

## 1회차 테스트 종료 기준

1. 홈 화면과 주요 메뉴를 모두 눌러봤다.
2. 기존 기출과 신규 기출을 각각 1개 이상 열었다.
3. 단답형, 서술형, 계산형, 소문항형 채점을 각각 1회 이상 실행했다.
4. 모의고사, OX, 플래시카드, 검색, 북마크, 오답노트를 최소 1회 이상 실행했다.
5. 발견 오류를 BUG 번호로 기록했다.
6. P0/P1 오류를 분리했다.
