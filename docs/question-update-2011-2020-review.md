## 2013~2015 처리 기준

2013~2015 자료는 본 기출 데이터에 바로 넣지 않는다.

이유:

1. 원문 문제와 요약자료가 섞였을 가능성이 높음
2. 법령·제도 개정 가능성이 큼
3. 2016~2020 후보와 중복되는 주제가 많음
4. 채점형 CBT 문제로 바로 쓰기에는 문항 구조가 불명확함

따라서 다음처럼 관리한다.

- 원문·정답 구조가 확인되면 `past_exam` 후보
- 개념형 자료는 `practice`
- 복원자료 기반 재구성 문제는 `mock_exam`
- 해설 중심 자료는 `summary`

2. 문제 텍스트 유사도 확인

4. 법령개정 태그 확인
5. 숫자형 채점 로직 적용 여부 확인
6. 계산형 문제의 반올림·단위 기준 확인

## 권장 병합 순서

### Step 1. Vite 전환 마무리

- `questions.js`를 `src/data/questions.js`로 이전
- `src/lib/scoring.js` 채점 로직 적용
- 숫자형 오판 방지 로직 반영

### Step 2. 업데이트 후보 통합

- `src/data/updates/questions-2020.js`
- `src/data/updates/questions-2019.js`
- `src/data/updates/questions-2018.js`
- `src/data/updates/questions-2017.js`
- `src/data/updates/questions-2016.js`
- `src/data/updates/questions-2011.js`

위 후보를 하나의 병합 스크립트로 합친다.

### Step 3. 본 데이터 병합

- 우선 병합 후보만 `src/data/questions.js`에 추가
- 보류 후보는 `src/data/updates/hold/` 또는 문서로 유지

### Step 4. Supabase 전환 준비

- `is_premium`
- `source_type`
- `source_year`
- `source_round`
- `review_status`
- `law_review_required`

필드 추가를 고려한다.
